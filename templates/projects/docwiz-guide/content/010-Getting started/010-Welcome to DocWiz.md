# Welcome to DocWiz

DocWiz turns one set of chapters into everything a delivered system needs: the full manual, a training slide deck, a one-page quick reference for the help desk, and an administrator guide with its data sheets. All of them come from the same text, so when you change a sentence once, every one of them changes with it.

This guide is itself a DocWiz project, and every chapter is written with the feature it describes: the chapter about building blocks is made of building blocks, and the chapter about slide decks comes with a real deck. Open the guide in the editor to see how each page is put together, or start your own copy of it and try things out — the original stays untouched.

## One source, many outputs {#one-source}

::: group The idea {#the-idea desc="Shown on the opening slides of the Getting Started deck"}
Most documentation gets written several times: once as the manual, again as slides for the training, and again as a cheat sheet for the help desk. Every copy drifts away from the others the moment something changes.

DocWiz keeps **one source** — the chapters of the manual — and builds everything else from it:

- the **manual**, numbered, searchable and cross-linked;
- **slide decks** for trainings, made from sections of the manual;
- **documents**: tidy one-page extracts for one audience;
- **attachments** such as PDF data sheets, shown right inside the handover;
- **documentation packages** such as an API reference, each in its own tab.
:::

Everything ends up in the **handover**: a folder of web pages that opens in any modern browser, works without internet and needs nothing installed. Hand it over on a USB stick, zip it into an e-mail or put it on a file share.

## Who reads what {#who-reads-what}

The readers of a manual are not all alike. DocWiz calls each group of readers an **audience**, and this guide has three of them:

{widths="25% 75%" caption="The audiences of this guide"}
| Audience | Who they are |
|----------|--------------|
| Author | Writes and updates chapters in the editor |
| Trainer | Builds slide decks and presents trainings |
| Administrator | Installs DocWiz, builds and ships handovers, uses the command line |

Each output is made for one audience. A chapter, a paragraph or even a single step can be marked for some audiences only: the manual still shows it, with a quiet "Only for …" note in the margin, while the outputs for everyone else leave it out. [Readers and audiences](dw:readers) explains how.

::: audience admin
The technical side of DocWiz — installation, the command line and the folder format — is in the *Administration* section and in the **Administrator Guide** tab of the handover.
:::
