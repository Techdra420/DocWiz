# Documentation packages

Some documentation is not written in DocWiz: an API reference generated from source code, a release-notes site, a supplier's online help. If it is a self-contained folder of web pages, DocWiz can ship it inside the handover, in a tab of its own, next to the manual.

This guide does exactly that: the **Command Line** tab of the handover is a documentation package — a small website listing every command and option of `docwiz`, kept in the project's `external\command-line` folder.

## Add a package {#add-a-package}

::: steps
1. In the sidebar, open **Outputs**. Under *Bundled with the handover*, click **Documentation packages**.
2. Click **Add package** and pick the package's folder.
3. Choose the **Type** — **API Reference**, **Release Notes** or **Integration Guide**. It becomes the title of the package's tab.
4. Choose **How to bundle it**. **Copy into the project** (recommended) copies the folder, so the project is complete on its own. **Reference the folder** leaves it where it is — handy when the folder is regenerated by another tool, but the folder must still be there whenever the handover is built.
5. Click **Add package**. If the project already has a package of that type, the button reads **Replace package** and says what will be replaced.
:::

The folder needs an entry page, called `handover.html` or `index.html`. The packages screen shows each package with its size and whether the entry page was found; **Open** shows it, **Remove** takes it out of the project.

## In the handover {#in-the-handover}

Each package gets a tab in the handover's header. Opening it shows the package's own pages, with a strip at the top leading back to the documentation. The package is shown exactly as it was made — DocWiz doesn't change or restyle it.

::: note
A package should work offline, like the rest of the handover: no links to fonts, scripts or pictures on the internet.
:::

## In the settings file {#settings-file}

Packages are listed under `external` in `docwiz.yaml`. The key becomes the tab's title — `command_line` shows as *Command Line*, `api_reference` as *API Reference* — so you are not limited to the three types the dialog offers:

```yaml
external:
  command_line: external/command-line
  api_reference: null        # no package of this type
```

**Check** warns when a package's folder is missing or has no entry page.
